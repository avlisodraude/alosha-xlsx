## Streaming vs buffered write

Generated by `pnpm bench:stream` (`bench/streaming.ts`) on 2026-07-08T14:58:35.943Z.

- Machine: Darwin 25.5.0 (arm64), Apple M3 Pro, 12 cores
- Node: v22.22.3
- Workload: a single sheet of 500,000 rows x 5 cols (2,500,000 cells), mixed types (string/number/boolean/date/formula), inline strings, written to a temp file
- Methodology: each mode runs in its own child process; peak RSS is `process.resourceUsage().maxRSS` (a per-process high-water mark), normalised to bytes; write time is wall-clock around the write (model construction included for buffered, since a buffered caller must materialise the whole model first)

| Mode | Write time | Throughput | Peak RSS | Output size |
| --- | --- | --- | --- | --- |
| streaming (`WorkbookWriter`) | 4.87 s | 102,630 rows/s | 191.0 MiB | 15.3 MiB |
| buffered (`writeWorkbookBuffer`) | 9.42 s | 53,054 rows/s | 2717.7 MiB | 15.0 MiB |

At 500,000 rows, streaming holds ~14.2x less peak memory than the buffered writer (which must retain the full model plus the whole output buffer), while sustaining 1.93x the write throughput. The streaming writer's memory stays roughly flat as rows grow; the buffered writer's grows with the sheet.

Run it yourself: `pnpm bench:stream` (set `BENCH_ROWS` / `BENCH_COLS` to vary the workload).
